# 국회 생중계 자막

[https://soju.day](https://soju.day)에서 방송 중인 국회 위원회의 실시간 자막과 오디오를 확인하고 날짜별 기록을 검색·저장할 수 있습니다.

서버 설치부터 PC·휴대폰 클라이언트 접속, HTTPS, 기존 데이터 이전까지는 [배포 안내](DEPLOY.md)를 참고하세요.
GitHub Actions를 이용한 테스트와 운영 서버 자동 배포는 [GitHub 공개와 자동 배포](GITHUB_DEPLOY.md)를 참고하세요.

서버가 국회 생중계 목록을 주기적으로 확인하고 ON AIR 위원회의 자막 WebSocket에 각각 접속해 받은 메시지와 문장별 최신본을 SQLite에 저장합니다. 브라우저에서 위원회 채널을 선택하면 해당 채널의 저장 기록과 실시간 자막·오디오를 재생합니다. 브라우저를 닫거나 화면의 수신을 일시정지해도 서버 수집은 계속됩니다.

**서버가 채널의 ON AIR 상태를 확인하고 수집을 시작한 이후의 자막만 보관됩니다.** 서버가 꺼져 있거나 원본 연결이 끊겨 있던 동안의 자막을 원본 서버에서 소급해서 가져오는 기능은 없습니다. 연결이 끊어지면 자동으로 재연결합니다.

오디오는 브라우저가 원본 방송 CDN에 직접 연결합니다. 이 서버에는 오디오 수집·변환·중계 기능이 없습니다.

## Linux + Docker 실행

이 폴더의 파일들을 서버의 작업 폴더로 복사하고 실행합니다. Docker와 Docker Compose가 설치되어 있어야 합니다.

```sh
docker compose up -d --build
docker compose logs -f --tail=100
```

브라우저에서 `http://서버주소:3000`으로 접속합니다. 이제 HTML 파일을 직접 열지 않고 이 서버 주소를 사용합니다. 서버는 `BROADCAST_LIST_URL`의 국회 생중계 목록을 30초마다 확인하고 방송 중인 각 위원회의 자막 WebSocket과 240p HLS 오디오 주소를 읽습니다.

컨테이너는 Docker가 시작되면 자동으로 다시 실행됩니다. 수집한 기록은 `caption-data` Docker 볼륨에 남으며, 컨테이너를 재생성해도 유지됩니다. 직접 `docker compose stop`으로 중지한 경우에는 다음 명령으로 다시 시작합니다.

```sh
docker compose up -d
```

포트, 방송 목록 주소나 갱신 주기를 바꾸려면 `.env.example`을 `.env`로 복사해서 수정합니다.

```sh
cp .env.example .env
# .env 파일 수정 후 적용
docker compose up -d --build
```

서버에서 자막 서버의 TCP 8091 포트로 나가는 연결이 가능해야 합니다. 중계가 없는 시간에는 자막이 오지 않을 수 있습니다. Docker 상태 점검은 웹 서버와 데이터베이스가 응답하는지 확인하며, 원본 자막 연결 상태는 화면과 `/api/status`에서 확인합니다.

## 웹 화면

- 접속 즉시 ON AIR 위원회 목록을 표시하고 저장된 마지막 선택 채널의 오늘 자막과 실시간 수신을 시작합니다. 마지막 채널은 브라우저 `localStorage`에 보관합니다.
- 화면 최상단에는 위원회 채널과 새로고침을 고정하고 최하단에는 자막 도구를 고정합니다. 가운데 자막 영역만 독립적으로 스크롤됩니다.
- 최상단에서 위원회 채널을 바꾸면 자막과 오디오가 함께 전환됩니다. ON AIR 채널이 있을 때 종료된 위원회는 목록에서 상태를 확인할 수 있지만 선택할 수 없습니다.
- ON AIR 채널이 하나도 없으면 오늘 중계가 예정되었거나 종료된 위원회를 선택해 방송 상태, 회의 제목과 저장된 자막 기록을 확인할 수 있습니다. 오늘 중계 일정이 전혀 없는 위원회는 목록에서 숨깁니다. 이 상태에서는 실시간 자막과 오디오가 비활성화됩니다.
- 서버와 브라우저가 30초마다 목록을 갱신하며, 상단의 `↻` 버튼으로 즉시 다시 확인할 수 있습니다.
- 기본 표시는 **실시간 · 문장별 최신본**입니다. 같은 `segment`의 초안과 뒤늦은 수정은 같은 문장에 반영됩니다.
- 날짜를 바꾸면 선택한 채널의 날짜별 저장 기록을 새로 불러옵니다. 날짜 기준은 한국 시간이며 과거 날짜에서는 실시간 스위치가 비활성화됩니다.
- `자막 재생` 스위치는 이 화면의 실시간 수신만 제어합니다. 다시 켜면 그 사이 서버가 수집한 기록도 불러옵니다. `오디오 듣기`도 같은 형태의 스위치로 제어합니다.
- 모바일에서는 실시간 재생 중 3.5초 동안 조작이 없으면 상단 채널과 하단 도구가 자동으로 접히고 자막 영역이 화면 전체로 넓어집니다. 화면을 만지거나 움직이거나 스크롤하면 다시 나타납니다. 일시정지, 과거 날짜 조회, 연결 복구 중에는 도구를 계속 표시합니다.
- 화면에는 시간과 수신 원본을 표시하지 않습니다. 검색, 자동 따라가기, 채널별 TXT 저장을 지원합니다.
- 다크테마와 상·하단 고정 도구를 사용합니다. 실제 상단·하단 높이를 측정해 가운데 자막 스크롤 영역의 경계를 맞춥니다.

TXT에는 선택한 채널의 문장별 최신본이 들어가며, ‘완성된 자막만’ 모드에서는 확정된 문장만 저장합니다.

## 화면 켜두기와 오디오

화면 켜두기는 Screen Wake Lock API를 사용합니다. **HTTPS와 지원하는 브라우저가 필요합니다.** `http://서버IP:3000`으로 접속하면 자막은 동작하지만 휴대폰 화면 유지 기능은 사용할 수 없습니다. 기존 HTTPS 리버스 프록시를 사용하거나 아래 설정 예시를 참고하세요. 절전 모드나 배터리 상태 때문에 운영체제가 화면 유지 요청을 거절할 수도 있습니다.

‘오디오 듣기’ 스위치는 사용자가 한 번 켜야 재생됩니다. 켬/끔 상태는 브라우저에 저장되어 새로고침하거나 채널을 변경해도 유지됩니다. 새로고침 후 브라우저가 자동 재생을 차단하면 스위치를 껐다가 다시 켜면 됩니다. Android Edge에는 브라우저의 HLS 지원 판정을 그대로 사용하는 대신 HLS.js를 우선 사용합니다. 재생기는 공개 CDN에서 불러오고, 실제 방송 데이터는 원본 방송 주소에서 브라우저로 직접 내려옵니다. 잠금 화면 재생·일시정지 제어도 지원합니다. Android 실기기의 재생 및 화면 잠금 상태까지는 이 개발 환경에서 검증하지 못했습니다. 백그라운드 재생은 Edge 및 휴대폰 설정에 따라 달라질 수 있습니다.

화면 유지 API 참고: [MDN Screen Wake Lock API](https://developer.mozilla.org/en-US/docs/Web/API/Screen_Wake_Lock_API). 미디어 제어 참고: [Media Session API](https://web.dev/articles/media-session).

## Nginx HTTPS 프록시 예시

기존 인증서와 도메인이 있는 경우 HTTPS 서버 블록 안에 다음을 사용합니다. 자막 실시간 응답을 즉시 전달하려면 버퍼링을 끕니다.

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 1h;
}
```

## 데이터와 백업

수집 파일은 컨테이너의 `/data/captions.sqlite`에 저장됩니다. SQLite의 WAL 파일도 같은 볼륨에 저장됩니다. 기록은 자동 삭제하지 않습니다.

전체 데이터베이스를 복사할 때는 수집을 잠시 멈춘 뒤 데이터 디렉터리 전체를 복사합니다.

```sh
docker compose stop
mkdir -p backup-data
docker compose cp assembly-live-captions:/data/. ./backup-data
docker compose up -d
```

`docker compose down -v`는 저장 볼륨까지 삭제하므로 기록을 남기려면 사용하지 않습니다.

## 직접 실행 및 검사

Node.js 24를 권장하며 Node.js 22.13 이상에서도 실행할 수 있습니다. 별도 npm 패키지는 필요하지 않습니다.

```sh
node server.mjs
npm test
```

직접 실행에서는 `data/captions.sqlite`에 저장합니다. `HOST`, `PORT`, `DATA_FILE`, `BROADCAST_LIST_URL`, `CHANNEL_REFRESH_MS` 환경변수를 사용할 수 있습니다.
